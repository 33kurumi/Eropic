## 维护规则（硬性）

1. **功能 ↔ 代码**：任何功能合入必须同时更新 `04-功能索引.md`（状态 + 代码入口）与 `features/<编号>-<名称>.md`。
2. **架构变更**：先写 ADR（不覆盖旧记录），再改 `02`。
3. **需求变更**：先改产品规划，再改开发文档，最后改代码。
4. **不写"以后补"**：代码地图里的文件/函数必须真实存在；未实现的功能状态标"规划中/推迟"。
