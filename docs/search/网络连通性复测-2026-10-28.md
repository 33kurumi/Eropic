## 3. 借这轮连通性顺带核实的事实（已订正到规划文档）

1. **Immich「重复工具」的自动预选规则**（docs.immich.app/features/duplicates-utility，已读到正文）：自动保留依据 = **字节更大的文件**、**EXIF 更多的文件**；元数据（名称/描述/相册/收藏）**只在「保留 1 张且至少废弃 1 张」时**从被废项同步到保留项，保留多张时不合并。→ 与 v0.1 文档 §2 的描述一致。
2. **PhotoPrism issue #1308**（"Duplicates: Display duplicated files with option to delete"）**仍为 open**，正文明确「能识别重复但不提供 UI 删除，只显示一个文件」→ 文档引用正确。
3. **Immich issue #24312**（新版 timeline 每次启动全量重载、无本地缩略图缓存）**已 closed**：作为「大库三条红线」的反面教材仍成立，但文档应知道它已被修复，不再作为现状引用。

5. **识图端点参考已拿到**：greasyfork 2998 脚本 = GitHub ccloli/Search-By-Image（★130，GPL-3.0，最后推送 2022-11-13），核心文件 search-by-image.user.js（27KB）已读；其 14 个 provider URL 模板（lens.google.com/uploadbyurl、graph.baidu.com/details、bing images/searchbyimage、tineye、yandex、pic.sogou、st.so.com、saucenao、iqdb、3d.iqdb、trace.moe、ascii2d、cydral、bget.ru 图床）与 app 内 core/search/OnlineImageSearch.kt 注释引用的模板一致；区别是脚本走「先传公共图床拿 URL 再拼 URL」，app 走「直接 multipart 上传」，后者更适合手机、也不依赖第三方图床。

## 5. 复测方法备忘（给以后的自己）

- GitHub 一律用 github_probe → github_file / github_api / github_issue，**不要**用 shell curl/git，也不要为此提权；匿名 60 次/小时，注意 rateLimit 字段。
- github_api 的 path **不能带查询串**（?recursive=1 会被拒），需要递归树就先读根目录再逐层下钻。
- web_fetch 对同一 URL 连试 3 次全超时就说明该域被网络层拦，**换镜像或换通道**，不要继续重试。
- 失效镜像清单（本轮实测）：ghproxy.net（不稳）、ghproxy.cc、raw.githack.com、cdn.jsdelivr.net、raw.iqiq.io、raw.gitmirror.com、statically.io（路径格式不符）。
- 可用镜像清单：gh-proxy.com（raw 文件）、developer.android.google.cn（Android 官方文档）。
## 6. 顺带做的「识图端点」交叉核对（GitHub 通了才有条件做）

对照两处可靠实现逐字段核对了 app 内 core/search/OnlineImageSearch.kt：

1. **Google Lens**：PicImageSearch（kitUIN/PicImageSearch，engines/google_lens.py，仍在维护）里明确写着注释 *"Google Lens currently returns 403 when upload requests include `hl`"*，上传端点是 `POST https://lens.google.com/v3/upload`、字段 `encoded_image`。→ 我们的代码原来带了 `hl=zh-CN`，**很可能一上传就 403**；已去掉 `hl`，保留 `stcs` 时间戳。
2. **ascii2d**：参考实现是 `POST https://ascii2d.net/search/file`、字段 `file`，成功后 302 到 `https://ascii2d.net/search/color/<hash>`（特征检索是 `/search/bovw/<hash>`）。→ 我们原来只判断最终 URL 里有没有 `uri=`，**会把成功结果误判成失败**；已改为同时接受 `/search/color`、`/search/bovw`、`uri=`。
3. **Yandex**：参考实现是 `POST https://yandex.com/images/search?rpt=imageview&cbir_page=sites` + 表单 `prg=1`、字段 `upfile`，然后直接取重定向后的最终 URL；我们目前用的是「`request=<JSON>` + 解析 `blocks[0].params.url`」的老办法。两种都能跑到结果页，但老办法是 2021 年前后的逆向结论、更容易随改版失效 —— **本轮不动**（改错了没法在桌面端验证），等真机试出问题再切。
4. **SauceNAO**：参考实现同样是 `POST https://saucenao.com/search.php` + `api_key` / `output_type=2` / `file`，和我们一致；差异只在「返回哪个链接」的选择策略（参考实现返回页面 URL，我们返回 `data.ext_urls[0]`，对手机更实用）。

两处已修（Lens 的 `hl`、ascii2d 的结果判断），改完重新构建 + 跑单测通过后才会提交。
